## Коротко

1. Актуальная версия Bot API — 10.3 от 24.08.2026. Для проекта важны: потоковый вывод ответа (`sendMessageDraft`, доступен всем ботам с 9.5 от 01.03.2026), структурированные сообщения (10.1, 11.06.2026), полноэкранные мини-приложения (8.0, 17.11.2024) [Т1, Т2, Т4].
2. Мини-приложение (Mini App — веб-страница, открытая внутри Telegram) — тот же конфигуратор, что на сайте, отдельной сборкой одного кода. Вход без пароля: сервер проверяет подпись `initData` ключом от токена бота. Данным `initDataUnsafe` доверять нельзя [Т3].
3. Оплата в боте. Telegram комиссию не берёт; сумы поддерживаются, один платёж — от 12 980,89 до 129 808 943,61 сум ($1,10–$11 026). Встроенная оплата через Payme требует кассы в Payme Business, а кассы дают только ИП и юрлицам. Звёзды Telegram (Stars) обязательны только для цифровых товаров; подбор, сборка и сетап — физическая услуга, Stars не нужны [Т5–Т8, Т22, Т23].
4. При выбранной владельцем схеме (вся сумма — владельцу) бот показывает смету двумя строками: «комплектующие по чекам» и «услуга 10–15 %», хранит фото чеков по каждому заказу и показывает их клиенту, ведёт счётчик годового оборота относительно порога 1 млрд сум ($84 940) [05: И1]. Пока владелец самозанятый — оплата по QR или счёту платформы с ручным подтверждением; кнопка оплаты внутри Telegram — после регистрации ИП.
5. Технология — grammY (TypeScript): общий код с сайтом (типы, расчёт цены, переводы, доступ к базе). aiogram (Python) так же свеж — поддерживает Bot API 10.3 — но добавляет второй язык в проект [Т13, Т14].
6. Бот владельца — та же программа: заявки приходят в закрытую группу владельца, каждая заявка — отдельная тема; ответ в теме уходит клиенту. Отдельный второй бот — по желанию.
7. Рассылки — только по отдельному согласию с кнопкой отписки в каждом сообщении. Правила Telegram запрещают непрошеные сообщения; Закон «О рекламе» требует согласия абонента при рекламе в услугах телекоммуникаций [Т8, Т31].
8. Ботов-конфигураторов ПК в Ташкенте поиск не нашёл: сборщики работают через каналы с ценами в долларах (блок 07). Из ботов EVOS, Uzum Tezkor, Click стоит взять выбор языка на старте, телефон кнопкой «Поделиться контактом», статусы заказа и напоминания.

### 1.2. Как бот поддерживает выбранную схему денег

- **О.** При схеме «вся сумма — владельцу» основная защита владельца — прозрачность цены комплектующих. Бот это обеспечивает:
  - смета всегда в двух строках: «комплектующие по чекам» и «услуга, 10–15 %»;
  - ставка услуги и правило выбора (10 или 15 %) хранятся в настройках, а не в тексте сообщений;
  - после закупки бот прикладывает фото каждого чека и пересчитывает итог по фактическим чекам; разница с предоплатой показывается клиенту (доплата или возврат);
  - акт передачи формируется из тех же данных: позиции, цены по чекам, серийные номера, гарантийные сроки поставщиков, гарантия владельца на работу.
- **Ф.** Режим самозанятого действует при доходе до 1 млрд сум ($84 940) в год; ставка налога с оборота 1 % с 01.01.2026 [05: И1, И2].
- **О.** Если вся сумма заказа учитывается как доход (оценка блока 02), порог достигается примерно за 33 заказа по 30 млн сум ($2 548). Поэтому в боте владельца нужен счётчик оборота с начала года с предупреждениями на 70 % и 90 % порога.
- **Ф.** Специальный QR самозанятого создаётся на платформе платёжной организации; подтверждённая платформа — Xolis в Paynet [05: И30–И35]. Встроенные платежи Telegram для самозанятого не подтверждены (см. 3.4).
- Номер личной карты бот не показывает ни в одном сценарии. Способ оплаты — только тот, что выбран по блоку 02b.

## 2. Бот владельца (администрирование)

### 2.1. Вариант устройства

- **О. Рекомендуемый вариант:** одна программа, один клиентский бот и закрытая группа владельца с темами (форум). Каждая новая заявка создаёт тему: карточка заявки, кнопки статусов, переписка. Сообщение владельца в теме бот пересылает клиенту от имени бота.
- Плюсы: один токен, одна база, история переписки привязана к заказу, можно добавить помощника без доступа к личному аккаунту владельца.
- Альтернатива: отдельный бот владельца. Нужен, если владелец хочет разделить права или вести несколько проектов.
- **Ф.** С Bot API 10.0 (08.05.2026) бот может управлять бизнес-аккаунтом без подписки Premium; через бизнес-подключение бот отвечает от имени личного аккаунта [Т1]. **О.** Для проекта не рекомендуется на старте: переписка смешивается с личными чатами, хуже учёт по заказам. Детали условий — не проверены.

### 3.2. Мини-приложения

- **Ф. Запуск:** кнопка меню бота, кнопка в клавиатуре, кнопка в сообщении, главное мини-приложение в профиле бота, прямая ссылка `?startapp=` с режимом `mode=compact` или `mode=fullscreen` [Т3, Т12].
- **Ф. Полноэкранный режим:** `requestFullscreen` / `exitFullscreen`, книжная и альбомная ориентация; отступы безопасной зоны `safeAreaInset` и `contentSafeAreaInset` [Т3, Т4].
- **Ф. Авторизация:** сервер проверяет строку `initData`: строка проверки из полей по алфавиту, ключ `HMAC-SHA256(<токен бота>, "WebAppData")`, сравнение с полем `hash`. Свежесть — по `auth_date`. Для проверки без токена есть подпись Ed25519 с открытыми ключами Telegram [Т3].
- **Ф.** «Data from this field should not be trusted» — про `initDataUnsafe`; использовать только проверенную `initData` на сервере [Т3].
- **Ф. Хранилища:** `CloudStorage` — до 1024 ключей на пользователя, значение до 4096 символов; `DeviceStorage` — 5 МБ; `SecureStorage` — 10 записей [Т3].
- **Ф. Данные:** мини-приложение автоматически получает IP-адрес пользователя; Telegram передаёт ID, имя, имя пользователя и фото профиля. Телефон, адрес, геопозицию пользователь передаёт сам [Т9].
- **Ф.** Платежи в мини-приложении проводят сторонние провайдеры, Telegram их не проводит [Т9].
- **О. Ограничения для проекта:**
  - встроенный браузер на недорогих Android-телефонах слабее настольного: для мини-приложения нужен облегчённый режим 3D (меньше полигонов, сжатые текстуры, статичные кадры вместо видео) и запасной вариант без 3D;
  - кинематографичная прокрутка с видео сайта в мини-приложении не нужна: конфигуратор — рабочий инструмент, лендинг остаётся на сайте;
  - кнопки «Назад» и основная нижняя кнопка — встроенные элементы Telegram; оформление следует теме пользователя (светлая/тёмная).
- **Ф.** Для попадания в подборки Telegram нужны главное мини-приложение, качественные материалы и приём оплаты в Stars [Т11]. **О.** Для проекта неприменимо: Stars не используются.

### 3.3. Ограничения частоты и доставки

- **Ф.** В одном чате — не чаще 1 сообщения в секунду; в группе — не больше 20 сообщений в минуту; массовые уведомления — около 30 сообщений в секунду. Платные рассылки до 1000 в секунду требуют 100 000 Stars на балансе и 100 000 активных пользователей в месяц [Т10].
- **О.** Для проекта лимитов достаточно; платные рассылки не нужны.
- **Ф.** Необработанные обновления Telegram хранит до 24 часов [Т2]. **О.** Простой сервера до нескольких часов не теряет заявки, если бот потом их заберёт.

| Payme (в BotFather — Paycom.Uz) | Нужен активный бизнес в Payme Business и отдельная касса для бота; тестовый режим без регистрации | [Т22] |
| Кто может получить кассу Payme | Только ИП, ЧП, ООО и другие организационные формы из списка; самозанятые в списке не названы | [Т23] |
| Click | Страница документации «Оплата через Telegram» есть, содержание 05.10.2026 не открылось; условия для самозанятого — не подтверждены | [Т24] |
| Список провайдеров по странам | Telegram не публикует; виден только в BotFather (служебный бот для настройки ботов) | [Т5]; блок 05 |

- **О.** Самая крупная сборка рынка в блоке 07 — около 56 млн сум за место ($4 757), ниже верхнего лимита одного платежа. Предоплату и остаток удобнее проводить отдельными счетами.
- **О.** Пока владелец самозанятый: счёт или QR платформы (Xolis) вне Telegram, бот хранит статус и ссылку, владелец подтверждает поступление. После ИП: встроенный счёт Telegram (`sendInvoice` или ссылка `createInvoiceLink`) через Payme или Click с фискальным чеком провайдера. Требования к чеку по каждой позиции комплектующих — не подтверждены, уточнить у провайдера при подключении.
- **Ф.** Споры и возвраты по встроенным платежам — ответственность владельца бота и провайдера; Telegram их не рассматривает [Т5, Т9].

### 3.5. Политика для ботов

- **Ф.** Боту нужна доступная политика конфиденциальности; если обработка отличается от стандартной политики Telegram — своя, указывается в BotFather (раздел 4) [Т8].
- **Ф.** Данные пользователей удаляются по запросу, когда больше не нужны, при закрытии бота — «без неоправданной задержки» (п. 4.2) [Т8]. Стандартный срок ответа на запросы — 30 дней (блок 04).
- **Ф.** Запрещено донимать пользователей непрошеными сообщениями (п. 5.2) [Т8].
- **Ф.** Запрещено собирать данные пользователей для обучения моделей ИИ; данные, которые пользователь передал сам, — только с явного, активного и отзываемого согласия (п. 4.3) [Т8].
- **Ф.** Нарушение правил — временная или постоянная блокировка (раздел 10) [Т8].
- **Ф.** Закон «О рекламе» ЗРУ-776 от 07.06.2022 (ред. от 11.03.2025): реклама при оказании услуг телекоммуникаций распространяется с согласия абонента (ст. 30); реклама должна быть отделена от другой информации; недостоверная реклама запрещена [Т31]. **О.** Распространяется ли ст. 30 на мессенджеры — не подтверждено; согласие на рассылку нужно в любом случае по правилам Telegram.
- **О.** Отзывы и «Идеи»: выдуманные отзывы и чужие фото как свои работы — недостоверная реклама (ст. 5 Закона) и нарушение авторского права (блок 04).

## 4. Технологии

### 4.1. grammY против aiogram

| Критерий | grammY (TypeScript) | aiogram (Python) |
|---|---|---|
| Свежесть | 1.46.0, поддержка Bot API 10.3, август 2026 [Т13] | 3.31.0, поддержка Bot API 10.3, август 2026 [Т14] |
| Общий код с сайтом | Типы, схемы проверки данных, расчёт цены, правила совместимости, переводы, доступ к базе — один пакет в монорепозитории (общем репозитории сайта и бота) | Дублирование расчёта цены и правил на Python или отдельный сервис |
| Диалоги из нескольких шагов | Плагины conversations (диалоги) и menu (интерактивные меню) [Т18] | Конечный автомат состояний (FSM) — сильная сторона |
| Сессии | Встроенные; адаптеры PostgreSQL, Redis, Prisma, Supabase и др.; «ленивые» сессии; срок жизни и миграции через `enhanceStorage` [Т15] | Хранилища FSM: память, Redis, MongoDB |
| Переводы | Плагин i18n на формате Fluent (`.ftl`) [Т17] | gettext и Babel (`.po`) [Т19] |
| Ограничения частоты | Плагин auto-retry, ограничитель частоты [Т18] | Встроенные средства и сторонние |

- **О.** Вывод: grammY. Главная причина — одна логика расчёта цены и совместимости для сайта, мини-приложения и бота. Расхождение цен между каналами — прямой риск недостоверной рекламы.
- **О.** aiogram был бы выбором, если бы весь проект писался на Python.

### 4.2. Получение обновлений: вебхук или длинный опрос

- **Ф.** Два способа: длинный опрос (long polling — бот сам запрашивает обновления) или вебхук (webhook — Telegram отправляет обновления на адрес сервера). Одновременно не работают [Т10].
- **Ф.** Порты вебхука: 443, 80, 88, 8443 [Т10]. Параметр `secret_token` (1–256 символов) приходит в заголовке `X-Telegram-Bot-Api-Secret-Token`; `max_connections` — 1–100 [Т2].
- **Ф.** Если вебхук не ответил вовремя, Telegram повторяет обновление. Внутренний предел grammY — 10 секунд; долгие операции — в очередь задач [Т16].
- **Ф.** Документация grammY: без особой причины для вебхуков длинный опрос не имеет серьёзных недостатков [Т16].
- **О. Для проекта:**
  - MVP на одном сервере (VPS) с сайтом — длинный опрос с плагином runner; без публичного адреса для бота;
  - при переходе на вебхук — HTTPS на порту 443, проверка `secret_token`, быстрый ответ, ответы ИИ и генерация PDF — в очередь;
  - повторная обработка одного обновления исключается проверкой `update_id`.

### 4.3. Хранение сессий и данных

- **О.** В сессии — только состояние диалога (шаг подбора, язык, черновик). Заявки, заказы, цены, чеки — в таблицах общей с сайтом базы PostgreSQL.
- **Ф.** Хранение сессий в памяти теряет их при перезапуске; для работы нужна база [Т15].
- **О.** Redis в MVP не нужен; адаптер PostgreSQL и «ленивые» сессии.
- **Ф.** Данные заявок можно хранить за пределами Узбекистана при условиях ст. 27-1 Закона о персональных данных; обязательная локализация с 27.03.2026 касается биометрии, генетики и данных абонентов связи (блок 04).
- **О.** В сообщениях бота — минимум персональных данных: полный адрес и телефон проходят через серверы Telegram. В группу владельца — район вместо адреса; адрес — по кнопке из базы.
- **О.** Фото чеков и гарантийные талоны — в хранилище файлов с доступом по ссылке с ограниченным сроком.

### 4.4. Локализация uz и ru

- **Ф.** Описание и список команд бота задаются по языкам (`setMyDescription`, `setMyCommands` с `language_code`) [Т11].
- **Ф.** Плагин i18n определяет язык: сохранённый в сессии → `language_code` клиента → язык по умолчанию [Т17].
- **О.** Узбекский интерфейс Telegram распространяется как языковой пакет (в выдаче поиска — «Uzbek» с адресом `uz-beta` и отдельно «Uzbek Cyrillic») [Т21; страницы не открывались]. Поэтому `language_code` у узбекоязычных пользователей часто будет `ru` или `en` (О). Язык спрашивать на старте и хранить в профиле.
- **О.** Состав языков: русский и узбекский на латинице. Кириллица — по спросу.
- **О.** Файлы переводов Fluent — общий пакет монорепозитория для сайта, мини-приложения и бота. Узбекский текст проверяет носитель языка до запуска.
- **О.** Названия комплектующих и характеристики не переводятся; переводятся пояснения и интерфейс.

## 6. Объём MVP

### 6.1. Входит

1. Старт: язык, согласие, политика, `/terms`, `/support`, `/privacy`.
2. Быстрый подбор кнопками → предварительная смета с датой цен.
3. Мини-приложение «Конфигуратор»: та же логика, что на сайте; облегчённое 3D или изображения; проверка `initData`.
4. Заявка → тема в группе владельца → переписка через бота.
5. Карточка заказа: статусы, уведомления, фото чеков, пересчёт по факту, акт передачи.
6. Оплата без встроенных платежей Telegram: инструкция и QR или счёт платформы, ручное подтверждение.
7. «Идеи» (только разрешённые) и «Портфолио» (концепты с пометкой).
8. Бот владельца: заявки, ответы, статусы, загрузка цен таблицей, напоминания (нет ответа 15 минут; неоплаченная смета 24 часа), счётчик оборота к порогу 1 млрд.
9. Русский и узбекский (латиница).

### 6.2. Этап 2

- ИИ-консультант с потоковым ответом и передачей человеку.
- Отзывы, рекомендации со скидкой, рассылки по подписке.
- Гарантийные случаи и напоминания о гарантийных сроках.
- Встроенная оплата Telegram через Payme или Click — после регистрации ИП.
- Правка цен в мини-приложении владельца.

### 6.3. Трудоёмкость

- **О.** MVP — 60–100 часов разработки при общем коде с сайтом, без ИИ-консультанта. ИИ-консультант — ещё 20–40 часов. Оценка без проверки на практике.
- **О.** По плану блока 10 первые клиенты приходят через бот и Instagram до готовности сайта. Порядок: быстрый подбор и заявки (1–2 недели) → карточка заказа и бот владельца → мини-приложение.

## Риски и решения

| Риск | Вероятность | Влияние | Решение |
|---|---|---|---|
| Деньги за всю сборку на счёте самозанятого: быстрое достижение порога 1 млрд сум и налог 1 % со всей суммы | Средняя | Высокое | Счётчик оборота в боте владельца с предупреждениями на 70 и 90 %; план перехода на ИП по блокам 01 и 02b |
| Оплата не тем способом (личная карта) | Средняя | Высокое | Бот показывает только выбранный законный способ; номер карты в шаблонах запрещён |
| Встроенная оплата Telegram недоступна самозанятому | Высокая | Среднее | Ручная оплата по QR или счёту платформы; встроенная — после ИП |
| Клиент сомневается в цене комплектующих | Средняя | Высокое | Фото всех чеков в карточке заказа, пересчёт по факту, акт передачи |
| Подделка данных в мини-приложении | Низкая | Высокое | Проверка `initData` на сервере, срок по `auth_date`, без `initDataUnsafe` |
| Блокировка бота за рассылки | Низкая | Высокое | Подписка отдельной кнопкой, отписка в каждом сообщении, не чаще 2 раз в месяц |
| Устаревшая цена в смете | Высокая | Среднее | Дата и срок действия в каждой смете; перепроверка цен перед выставлением счёта |
| ИИ-консультант ошибается в совместимости или цене | Средняя | Среднее | Ответ из правил совместимости и снимка цен; предупреждение; кнопка «Позвать человека»; ИИ не называет итоговую цену |
| Утечка персональных данных | Низкая | Высокое | Минимум данных в сообщениях, доступ по списку ID, журнал действий; уведомление госоргана за 24 и 72 часа (блок 04) |
| Чужие посты в «Идеях» без разрешения | Средняя | Среднее | Только письменные разрешения; иначе ссылка без предпросмотра |
| Тяжёлое 3D не работает на недорогих телефонах | Средняя | Среднее | Облегчённый режим и запасной вариант с изображениями |
| Ошибки узбекского перевода | Средняя | Среднее | Проверка носителем языка; одна база переводов для всех каналов |
| Повторы обновлений при вебхуке, долгие ответы ИИ | Средняя | Низкое | Длинный опрос в MVP; при вебхуке — очередь и проверка `update_id` |
| Потеря доступа к аккаунту владельца или токену | Низкая | Высокое | Двухэтапная проверка, второй администратор группы, токен в хранилище секретов, сайт как запасной канал |

## 2. Реализация

### 2.1. Четыре способа связать анимацию с прокруткой

| Способ | Как работает | Плюсы | Минусы | Где применять |
|---|---|---|---|---|
| Секвенция кадров на canvas | Предзагрузка N картинок, номер кадра = доля прокрутки | Точный кадр, одинаково во всех браузерах | Много запросов и вес; память на телефонах | Короткие сцены до 60–90 кадров; запасной вариант |
| Перемотка видео (`video.currentTime`) | Одно MP4, время видео = доля прокрутки | Вес почти в 5 раз меньше, 2 запроса [5] | Частые ключевые кадры; сервер с HTTP Range (ответ 206); для плавной перемотки видео должно быть загружено целиком или почти целиком [5] | **Основной способ для главной** |
| WebCodecs (`VideoDecoder`) | Видео декодируется в кадры в памяти, кадры рисуются на canvas | Точность секвенции при весе видео | Сложнее в коде; Safari — видео-часть с 16.4, полностью с 26.0 [16] | Если перемотка дёргается на тестовых телефонах |
| CSS-анимации по прокрутке (`animation-timeline`) | Анимация CSS идёт по прокрутке без JS | Лёгкие, без библиотек | Firefox — нет в стабильной версии (не подтверждено окончательно); нужны `@supports` [17][18] | Появление текста, полосы прогресса |

**Факт.** Замер LearnWithHasan (31.07.2026), ролик Veo 3.1, 8 с × 24 к/с = 192 кадра, выдача 720p из исходника 1080p [5]:

| Показатель | Видео H.264, `-g 8` | Секвенция WebP q60 |
|---|---|---|
| Вес | 849 КБ | 4 010 КБ |
| HTTP-запросы | 2 | 193 |
| Время до первой отрисовки | 117 мс | 585 мс |
| Разброс времени прокрутки (5 прогонов, 4× замедление ЦП, экран 412×915) | 43 мс | 626 мс |

- Ключевой кадр каждые 8 кадров (`-g 8`) снизил время одной перемотки с 57 до 14 мс при замедленном ЦП — в пределах бюджета кадра 16,7 мс [5].
- **Оговорка.** Замер — один автор, эмуляция в Chrome DevTools на настольном компьютере. Аппаратный декодер среднего Android так не воспроизводится. Цифры — ориентир; решение принимать по замеру прототипа на реальных телефонах (раздел 2.5).
- **Оценка.** «2 запроса» не означают быструю первую перемотку на плохой связи: пока видео не загружено, перемотка упирается в сеть. Поэтому видео грузится заранее, до подхода к секции (раздел 2.4), а до готовности показывается постер.
- Ошибки из того же гайда: прямое присваивание `currentTime` в обработчике прокрутки (решение — очередь по событию `seeked`); локальный сервер без Range-запросов [5].
- **Факт.** Перемотка лучше всего работает в Safari, затем Chrome, затем Firefox; в Firefox MP4 дёргается [9].

Пример подготовки видео (параметры подобрать на тестах):

```bash
# видео для перемотки: ключевой кадр каждые 8 кадров, без звука, быстрый старт
ffmpeg -i hero.mp4 -an -c:v libx264 -crf 23 -preset slow -g 8 -keyint_min 8 -sc_threshold 0 \
  -vf "scale=1280:-2" -movflags +faststart hero-720.mp4

# запасная секвенция: 24 к/с, ширина 1280, WebP качество 70
ffmpeg -i hero.mp4 -vf "fps=24,scale=1280:-2" -c:v libwebp -quality 70 frames/f_%04d.webp
```

Схема перемотки без рывков (суть):

```js
// прокрутка задаёт целевое время; новое присваивание — только после события seeked
let target = 0, busy = false;
ScrollTrigger.create({ trigger: "#hero", start: "top top", end: "+=300%", pin: true,
  onUpdate: s => { target = s.progress * video.duration; seek(); } });
video.addEventListener("seeked", () => { busy = false; seek(); });
function seek() { if (busy || Math.abs(video.currentTime - target) < 0.02) return;
  busy = true; video.currentTime = target; }
```

### 2.2. Библиотеки

| Библиотека | Статус | Что даёт | Источник |
|---|---|---|---|
| GSAP + ScrollTrigger | Бесплатно с версии 3.13 (апрель–май 2025), включая коммерческое использование и бывшие платные плагины. Запрет — только на визуальные конструкторы анимаций, конкурирующие с Webflow; сайта студии не касается | Закрепление секций (`pin`), привязка к прокрутке (`scrub`), временные шкалы | [19][41] |
| Lenis 1.3.26 | Лицензия MIT | Сглаженная прокрутка; синхронизация с ScrollTrigger через `gsap.ticker`; учитывает `prefers-reduced-motion` | [20] |
| CSS `animation-timeline` | Chrome/Edge с 115, Safari с 26 | Анимация по прокрутке без JS | [17][18] |

- **Факт.** Ограничения Lenis: в Safari не выше 60 к/с, в режиме энергосбережения — 30 к/с; нет CSS scroll-snap без плагина; сбои касаний на iOS ниже 16 [20].
- **Оценка.** Lenis не обязателен. На Android сглаживание часто мешает: прокрутка запаздывает за пальцем. Включать только на десктопе.
- **Оценка.** Анти-список: без стеклянных панелей поверх видео, свечений, вращающихся колец. Текст поверх кадра — на плотной подложке или в свободной зоне кадра.

### 2.3. Число кадров, форматы, вес

| Параметр | Десктоп | Средний Android / iPhone | Основание |
|---|---|---|---|
| Длительность сцены | 8–12 с видео | Та же сцена, меньше разрешение | Оценка; 8 с в замере [5] |
| Частота кадров | 24 к/с | 24 к/с | [5][7] |
| Кадров в сцене | 190–290 | 190–290 (видео) или 60–90 (секвенция, через кадр) | [5][6] |
| Разрешение | 1920×1080 | 1280×720 (горизонт.) или 720×1280 (вертик.) | [5] |
| Формат | MP4 H.264, `-g 8`; секвенция — AVIF или WebP | MP4 H.264 | [5][9] |
| Вес главной сцены | 2–4 МБ (оценка) | 0,8–1,5 МБ (оценка по 849 КБ за 8 с 720p) | [5] |
| Первый экран (до прокрутки) | Постер AVIF 150–250 КБ | Постер AVIF 60–120 КБ | Оценка |

- **Оценка.** AVIF для постеров обычно легче WebP при том же качестве, но кодируется дольше. Для секвенций WebP проще в сборке.
- **Оценка.** Вертикальная версия сцены (9:16) на телефоне выглядит лучше обрезанной горизонтальной. В Blender это вторая камера.
- H.264 выбран из-за аппаратного декодирования на всех телефонах. Поддержка и скорость перемотки AV1 и HEVC на средних Android не проверены (не подтверждено).

### 2.4. Предзагрузка и экономия трафика

- Первый экран — постер и HTML-текст. Это главный элемент для LCP (время отрисовки крупнейшего элемента).
- Видео сцены грузится после LCP и до подхода к секции (IntersectionObserver с запасом в 1–2 экрана); `preload="auto"` — после первого взаимодействия или 1–2 с простоя. Пока видео не загружено, прокрутка показывает постер.
- Режим экономии: `navigator.connection.saveData`, заголовок `Save-Data` или `effectiveType` = 2g/3g — 5–7 статичных кадров с текстом вместо видео.
- **Факт.** Медианная скорость мобильного интернета в Узбекистане — 61,03 Мбит/с (май 2026), 77-е место в мире [21]. **Оценка.** 1,5 МБ при такой скорости — меньше секунды, но в метро и на окраинах скорость ниже; режим экономии нужен.
- CDN (сеть доставки контента) с долгим кэшем, имена файлов с хэшем версии. Сервер обязан отдавать Range-запросы (ответ 206), иначе перемотка не работает [5].
- Бюджет: главная целиком до 3 МБ на телефоне (оценка).

### 2.5. Поведение на средних Android и iPhone

- **Факт.** Android — 83,14 %, iOS — 16,85 % мобильного трафика Узбекистана (StatCounter, август 2026) [22].
- **Оценка.** Тестовые телефоны — средний Android за 2–3 млн сум (Samsung Galaxy A, Redmi Note) и iPhone 12–13. Эмуляция DevTools (4× замедление ЦП, экран 412×915) — только предварительная проверка; итоговый замер — на реальных устройствах.
- iOS: видео `muted playsinline`; в режиме энергосбережения анимации ограничены 30 к/с [20].
- Секвенция кадров опасна по памяти: 200 кадров 1280×720 в распакованном виде — около 700 МБ (оценка: 1280×720×4 байта ×200). Если секвенция — держать в памяти окно из 20–30 кадров.
- 3D-конфигуратор на слабых устройствах: `dpr` (плотность пикселей) 1–1,5, без теней в реальном времени, при низком FPS — 2D-режим.

### 2.6. Доступность

- `prefers-reduced-motion: reduce` — анимация по прокрутке отключается, вместо неё 5–7 статичных кадров с подписями. WebKit предупреждает: чем больше площадь движения, тем выше риск дискомфорта [18].
- Весь текст — в HTML. Видео декоративное (`aria-hidden="true"`), смысл продублирован текстом.
- Закреплённая секция не «запирает» клавиатуру: Tab, Page Down, пробел работают; есть ссылка «Пропустить анимацию».
- Контраст текста поверх кадра — не ниже 4,5:1 (WCAG 2.2 AA).
- Конфигуратор: каждая деталь выбирается из списка, 3D — дополнительный вид.

### 3.2. Качество для предметной съёмки «железа»

- **Оценка (по гайдам и типовым дефектам моделей).** ИИ-видео плохо держит мелкую геометрию: текст на платах, число разъёмов, лопасти вентиляторов, рёбра радиаторов, ход кабелей. Деталь «переделывается» между кадрами [10].
- На кадре может оказаться деталь, которой нет в продаже. Блок 04 требует показывать только конфигурации, которые реально собрать в Ташкенте.
- Вывод: точный показ ПК — рендер Blender. ИИ-видео — комната, свет, время суток, движение камеры по интерьеру.

### 3.3. Альтернативы ИИ и кто делает 3D

| Источник | Плюсы | Минусы | Цена |
|---|---|---|---|
| Рендер в Blender своих моделей | Точная геометрия, любой ракурс, те же модели идут в конфигуратор; нет водяных знаков | Нужен навык 3D; 40–80 часов на набор моделей и анимацию (оценка); время рендера | Blender бесплатен (GPL; права на рендеры у автора — не проверено на blender.org) |
| Купленные модели + анимация в Blender | Быстрее: моделирование заменяется покупкой, остаётся сборка сцены и анимация | Лицензии разные: CC-BY требует указания автора; логотипы брендов; не все лицензии разрешают рекламу и переработку | RenderHub — расширенная лицензия, glb/gltf, корпуса Corsair [35]; Sketchfab — 800 тыс. бесплатных моделей по Creative Commons [36] |
| Подрядчик-3D-художник | Владельцу не нужен навык | Цена и сроки в Ташкенте не исследованы — не подтверждено | Запросить 2–3 сметы на сцену 10–12 с и 8–10 моделей |
| Реальная съёмка своих сборок | Максимальное доверие; годится в «Портфолио» | Нужны первые заказы, свет, штатив | Оценка: 1,5–4 млн сум |

- **Оценка.** Логотипы брендов на моделях и рендерах — риск по товарным знакам (блок 04). На главной — модели без логотипов; бренды — только в конфигураторе как названия товаров.
- **Не подтверждено.** Есть ли у владельца навык 3D. От ответа зависит срок концепции А (раздел 5).

### 3.4. Как получить согласованную серию кадров

1. Оба ключевых кадра — из одного исходника: один рендер или одна сцена, отредактированная во второй кадр. Одинаковое разрешение и соотношение сторон [10][37].
2. Кадры близки: тот же объект, масштаб, композиция. Переход «крупный план → общий план» за 5 с ведёт к искажениям [37].
3. «Опора» — элемент, который не меняется весь ролик (корпус, стол, положение камеры) [10].
4. Промпт описывает только переход, движение камеры, свет и то, что остаётся неизменным [10][37].
5. Свет одинаковый на обоих кадрах, иначе мерцание [37].
6. Цепочка сцен: последний кадр ролика N — первый кадр ролика N+1.
7. 3–5 генераций на годный ролик [3]. Veo не даёт задать seed (число для повтора результата): удачный ролик сохранять сразу [5].
8. После генерации — один LUT (таблица цветов) на все ролики, лёгкое зерно, проверка по чек-листу (раздел 6).

### 4.1. Конфигуратор в 3D

- Сцена: стол, корпус, слоты деталей. Каждая категория — отдельный glTF, загружается при выборе.
- Смена детали: анимация установки 0,3–0,6 с, камера подъезжает к слоту.
- Подсветка выбранной детали — светом и затемнением остального, без неонового контура.
- Разнесённая схема: детали разъезжаются по осям, подписи — HTML поверх сцены [12].
- RGB внутри корпуса: «выкл.», «белый тёплый», «цвет клиента»; по умолчанию выкл. или белый.
- Производительность: рендер по запросу (`frameloop="demand"`) [38]; геометрия — meshopt (быстрее Draco при распаковке) [38]; текстуры — KTX2, остаются сжатыми в памяти ГП [38][39].
- **Факт.** Пример 2026 года: конфигуратор на three.js ужат с 16,7 до 2,4 МБ (−86 %), 60 к/с на средних Android; основной вклад — текстуры (80 %+) [39].
- Бюджет (оценка): первая загрузка до 3–5 МБ; деталь — 100–400 КБ; до 100 вызовов отрисовки на кадр; повторяющиеся элементы — `InstancedMesh`.
- Модели упрощённые, по габаритам из спецификаций, без мелкого текста.
- 2D-режим для слабых устройств и `prefers-reduced-motion`: список деталей с фото и ценами.
- Цены в конфигураторе показываются двумя строками: «Комплектующие (ориентир по ценам магазинов)» и «Работа (10–15 %)» — см. раздел 7.

### 4.2. Где видео, где 3D

- Видео — сюжет задан заранее (главная, услуги, соцсети).
- 3D — пользователь выбирает (конфигуратор, сравнение корпусов).
- Один набор моделей кормит и видео, и 3D (оценка: экономия работы, единый вид).

## 6. Как сделать, чтобы визуализации не выглядели «сгенерированными ИИ»

**Свет**
- Один основной источник с понятным направлением: окно днём или софтбокс. Мягкие тени.
- Без цветных контровых свечений, неона, светящегося тумана.
- Подсветка ПК — выключена или тёплая белая; цвет — только в конфигураторе.

**Материалы**
- Дерево стола с текстурой, матовый алюминий, закалённое стекло с честными отражениями, оплётка кабелей, войлок.
- Лёгкие несовершенства: микроцарапины, неровность отражений, пыль на дальнем плане.

**Камера**
- Фокусные расстояния предметной съёмки: 35–85 мм, f/4–f/8; без сверхширокого угла и сильного размытия фона.
- Движение как с тележки или штатива: наезд, отъезд, панорама. Без пролётов сквозь стекло.
- Высота камеры — уровень глаз сидящего человека или стола.

**Сюжет и детали**
- Ташкентский контекст: реальная планировка, розетки типа C/F, окно без узнаваемых чужих объектов.
- Никакого сгенерированного текста: надписи либо настоящие (вставлены в монтаже), либо отсутствуют.
- Число разъёмов, вентиляторов, слотов — как у реальной детали из конфигуратора.

**Обработка**
- Один LUT на все материалы, лёгкое зерно, без перенасыщенности.

**Чек-лист отбраковки кадра**
- Деталь меняет форму; кабель исчезает или срастается; лопасти «плывут»; бессмысленные надписи; свет меняет направление; руки деформированы. Любой пункт — кадр в брак.

**Пометка**
- На каждом ИИ-кадре и рендере — подпись «Визуализация» в углу, читаемая на телефоне; в подписях соцсетей — тоже (блоки 03, 04, 11).
- Визуализации не попадают в «Портфолио»; 3D-концепты — только с пометкой «концепт».
- Метаданные C2PA и невидимые знаки (SynthID и аналоги) не удаляются.
- В `alt` и подписи: «Визуализация. Пример сборки, не выполненный заказ».

## 7. Как это работает при решениях владельца

Блок 20 — о визуальной части сайта. С решениями владельца он пересекается в подписях, сметах и в учёте собственных расходов. Блок 02 рекомендовал схему, где клиент платит магазинам сам; владелец выбрал другую: вся сумма — владельцу. Отдельный разбор схемы (`02b-shema-deneg-otvetstvennost.md`) на 05.10.2026 в папке исследований не найден, поэтому ниже — опора на блок 02 и ссылки на него.

**Что следует из выбранной схемы для сайта (по блоку 02)**
- Если владелец получает всю сумму и покупает детали на себя, вся сумма — его выручка (НК ст. 463, 465), а перед клиентом он отвечает как продавец: чек на всю сумму, претензии по товару — к нему, обмен в течение 10 дней (ЗоЗПП ст. 10, 13, 18; блок 02, раздел 2.3).
- Для самозанятого перепродажа новых комплектующих — вне перечня видов деятельности (блок 02). Законный путь для выбранной схемы — ИП или ООО с кассой и учётом товара (блоки 01, 02). Сайт с подписями «покупаем сами» и «оплата одной суммой нам» запускать после регистрации в этой форме; в подвале сайта и в оферте — реквизиты ИП или ООО.
- Вариант без смены формы — поручение с деньгами клиента (ГК ст. 817–820) — блок 02 оценивает как высокорисковый. Если его всё же выбирают, подписи на сайте должны говорить «покупаем от вашего имени», а чеки и гарантийные талоны — на клиента. Подписи концепций А и В в этом случае переписать.

**Формулировки на сайте (под схему «вся сумма владельцу, закупка на себя»)**

| Где | Формулировка | Почему так |
|---|---|---|
| Концепция А, кадр 3 | «Покупаем сами. Копии чеков магазинов — вам» | Чеки магазинов выписаны на владельца; клиенту — копии как подтверждение цены и его фискальный чек на всю сумму |
| Концепция А, кадр 4; конфигуратор | «Детали — по цене чеков. Наша работа — 10–15 % от стоимости сборки» | Цена работы указывается отдельно от цены деталей (блок 02); объявленная цена работы не может быть выше прейскуранта (ГК ст. 662) |
| Концепция А, кадр 5 | «Одно окно: гарантийные вопросы решаем мы» | Владелец отвечает как продавец и сам предъявляет претензии магазинам |
| Концепция В, шаг 3 | «Договор и оплата одной суммой нам, с фискальным чеком» | Каждый платёж — с чеком (НК ст. 221; блок 02) |
| Конфигуратор, итог | Две строки: «Комплектующие — ориентир по ценам магазинов на дату расчёта» и «Работа — N % от стоимости сборки» | Цены магазинов меняются; окончательная сумма — по чекам на дату закупки |

- **Оценка.** «Без наценки» и «по цене чеков» — утверждения в рекламе, их нужно уметь подтвердить. Хранить чеки и связывать их с заказом. Если магазин дал владельцу скидку или бонус, передавать его клиенту, иначе подпись перестаёт быть правдой. Требования Закона «О рекламе» к таким утверждениям в этом блоке не проверены (не подтверждено; см. блок 04).
- **Не подтверждено.** База процента: «от стоимости сборки» можно понять как стоимость деталей или как стоимость деталей вместе с работой. До публикации зафиксировать в оферте одно определение (рекомендация: процент от суммы чеков на комплектующие) и повторить его дословно на сайте, в боте и в смете.
- Гарантия: на сайте не обещать «гарантию производителя от нас» (блок 02). Формулировка: «Срок гарантии на детали — по талонам производителей. Принимаем ПК, сами обращаемся в магазин, возвращаем исправным. На сборку — наша гарантия 12 месяцев» (срок — решение владельца по блоку 02).

**Расходы на визуальную часть**
- Подписки на ИИ-сервисы, модели, работа подрядчика по 3D — расходы владельца из его платы за услугу. В смету клиента не включаются, иначе «детали по цене чеков, работа 10–15 %» перестаёт быть правдой.
- **Оценка.** При сборке на 18 млн сум плата 10–15 % — 1,8–2,7 млн сум. Подписка Runway Standard (176 594 сум в месяц) или Google AI Plus окупается одной сборкой. Подрядчик по 3D для концепции А — разовая сумма, её нужно сопоставить с ожидаемым числом сборок в первые месяцы (цена подрядчика не исследована).

## Рекомендация

1. Главная: концепция А «ПК собирается при прокрутке» на рендерах Blender, ниже — концепция В «Путь от заявки до сетапа». Концепция Б — для страницы «Сетапы» после первых заказов.
2. До старта А решить, кто делает 3D: сам владелец, подрядчик (запросить 2–3 сметы) или купленные модели плюс анимация. Если А не успевает к запуску сайта, первым экраном временно ставится В.
3. Техника: перемотка видео H.264 с ключевым кадром каждые 8 кадров, GSAP ScrollTrigger с закреплением, текст в HTML. Секвенция кадров — запасной вариант; WebCodecs — если реальные Android покажут рывки.
4. Lenis — только на десктопе.
5. Бюджет веса: главная до 3 МБ на телефоне, постер как LCP, видео грузится до подхода к секции; режим экономии и `prefers-reduced-motion` — статичные кадры.
6. Конфигуратор: React Three Fiber + drei, glTF на каждую деталь, meshopt + KTX2, рендер по запросу, 2D-режим; цена — две строки: детали и работа.
7. ИИ-видео для атмосферы: Runway Standard (без знака, коммерческое право в условиях). Google (AI Plus или Gemini API) — после пробной генерации без видимого знака. Seedance — после проверки оплаты из Ташкента и условий. Kling — не использовать.
8. Подписи о деньгах и гарантии — по разделу 7, после выбора формы работы по блоку 02; формулировки сайта, бота и оферты совпадают дословно.
9. Каждый ИИ-кадр и рендер — с пометкой «Визуализация»; условия сервисов — в PDF в реестр лицензий.
10. До разработки: прототип одной сцены 8–10 с и замер на реальных Android и iPhone.

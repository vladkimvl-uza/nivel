# Nivel — дизайн-система «Ночь и день» (В + А)

Версия 1.1 · 06.10.2026 (после рецензии арт-директора и замера скорости) · источник истины — `index.html` рядом с этим файлом (прототип), кадры — `frames/`, проверка — `shots/`.

> **06.10.2026 владелец изменил решение: сайт только ночной** («без дневной версии»). Первый экран — его видео на прокрутке вместо 3D-сцены. Действуют ночные роли цветов, типографика, сетка, компоненты и документальные блоки; дневной режим, выбор по времени и переключатель сняты (ADR-006). Разделы про день и 3D-сцену — история.

Решение владельца 05.10.2026: одна 3D-сцена рабочего места в двух режимах. Днём — светлая «Мастерская» (солнце из окна, тени рамы). Вечером — «Ночная съёмка» (лампа зажигается и раскрывает стол). Документальные блоки взяты из «Паспорта сборки»: смета со штампами, отчёт по чекам, паспорт с протоколом тестов.

Главное правило: **одна студия в разное время суток, а не два сайта**. Между режимами меняются только роли цветов и свет сцены. Типографика, сетка, отступы, компоненты, тексты и путь камеры одни и те же.

## 2. Токены

### 2.1. CSS custom properties

Режим задаётся атрибутом `data-theme="day|night"` на `<html>`. Компоненты используют **только ролевые токены**, никогда сырые цвета (исключение — документы: они всегда «бумага», см. 3.6).

  --logo-day:0; --logo-night:1;

Почему так:

- **Ночь — тёплый чёрный**: у всех тёмных тонов R ≥ G ≥ B (`#121110`, `#0E0C0B`, `#1A1816`). Синих, navy, фиолетовых, бирюзовых нет ни в CSS, ни в сцене (проверяется скриптом: ни одного hex с B > R).
- **Документы ночью остаются бумагой** (`--doc:#E9E3D7` — чуть приглушённый, «под лампой»), поэтому смета, отчёт и паспорт одинаково читаются в обоих режимах и связывают их.
- Акцент на светлом фоне для текста — `--accent-ink:#A53F17` (контраст 5,5:1 на `#F1EFEA`, 5,0:1 на `--bg-2`; до 06.10.2026 был `#B4481A` — 4,3:1 на `--bg-2`, не проходил AA), для заливок, знака и крупного текста — `#D9501A` (3,6:1 — мелким текстом на светлом не использовать). Ночью `#F06A30` на `#121110` — 6,1:1.
- Контраст основного текста: день `#1D1D1B / #F1EFEA` ≈ 14,7:1; ночь `#F1EFEA / #121110` ≈ 16,4:1; вторичный `--ink-2` ≥ 6:1 в обоих режимах.

### 2.4. Отступы и сетка

- Контейнер `.wrap`: `max-width:1320px`, поля `--gut` = `clamp(16px, 4vw, 56px)` (16 px на телефоне).
- Секция: `padding: clamp(80px, 10vw, 140px) 0`. Шапка секции → контент: `clamp(40px, 5vw, 64px)`.
- Шаг внутри компонентов: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 56 · 80.
- Точки перелома: 1180 (шаги 6 → 3 колонки), 1100 (меню → бургер), 960 (две колонки → одна), 860 (раскладка сцены «телефон»), 640/600/560/520 (таблицы и сетки в столбец), 420.
- Никакой горизонтальной прокрутки: `main, .ftr { overflow-x: clip }` (штампы до оттиска масштабируются ×1,6 и иначе расширяют страницу на телефоне).

### 2.5. Радиусы и тени

- Радиусы: 2 px (кнопки, чипы, бирки, сегменты), 3 px (карточки конфигуратора и идей), **0 у документов** (бумага).
- Тени только «бумажные», снизу, без цветного свечения: `--doc-shadow` для документов, `--card-shadow` для карточки сметы. Ночью тени глубже (лист лежит под лампой). Никаких `blur()`, `backdrop-filter`, неона, стекла.

## 3. Компоненты

### 3.1. Кнопки `.btn`
- Основная: заливка `--btn-bg`, текст `--btn-ink`, высота 52 px (малая 40 px, на телефоне в сцене 44 px), радиус 2 px, слева знак `.mk`. Днём — асфальт, ночью — бумага: кнопка «выворачивается», как свет лампы.
- Вторичная `.btn--ghost`: прозрачная, рамка `--line-2`; в сцене подложка `--chip-bg`, чтобы читаться поверх 3D.
- Наведение — только смена фона/рамки за `--dur-2`. Без подъёма, без тени, без градиента.
- Главная CTA — «Рассчитать сетап» (ведёт в конфигуратор в режиме «Сетап»); в карточке — «Получить смету в Telegram» (ссылка на `t.me/niveluzbot?start=cfg_…`).

### 3.2. Переключатели `.seg2`, `.seg`, `.chip`
- День/ночь — две кнопки с SVG-иконками (солнце 8 лучей, месяц), `aria-pressed`, `aria-label`. Без эмодзи. Активная — заливка `--ink`, иконка `--bg`.
- RU/UZ — тот же сегмент, моноширинный 13 px.
- Чипы задач и сегменты стиля: рамка `--line-2`, выбранный — заливка `--ink`.

### 3.3. Карточки
- `.card` (смета конфигуратора): `--surface`, рамка `--line`, радиус 3, `--card-shadow`, на ≥ 961 px липкая (`top: head + 20px`). Шапка → позиции (пунктир между строками) → итоги на `--bg` с верхней линией `--ink`.
- `.idea` (Идеи): шапка автора (аватар-заглушка пунктиром, `@автор_N`, «Instagram · с разрешения автора»), поле встраивания 4:5 с биркой «заглушка встраивания · чертёж Nivel», тело с тегами, ценой «пример» и кнопкой «Собрать похожий».
- **Запрещено:** цветные полосы на карточках, иконки-эмодзи, «стеклянные» подложки, кольца/орбиты, градиентные заставки.

### 3.4. Таблицы
- Заголовки — моно 10 px, ВЕРХНИЙ РЕГИСТР, +0.06em, `--doc-ink-2`, нижняя линия 1,5 px `--doc-ink`.
- Строки — линия 1 px `--doc-line`, числа справа моно 13 px, у числовых колонок `padding-left:10px` (иначе соседние заголовки «Чек»/«Разница» слипаются на телефоне).
- Итог — двойная линия `3px double`, 500. Возврат клиенту — цвет `#9C3A12`, 500.
- На ≤ 600 px шкала платы перестраивается в карточки-строки (`display:grid`), второстепенные колонки скрываются `.hide-s`.

### 3.5. Штампы
Три вида, все — «чернилами» через SVG-фильтр `#ink` (feTurbulence → маска; неровный оттиск **без размытия и свечения**):
- `.stamp-r` прямоугольный двойной: слово (Fira Sans Extra Condensed 700) + дата и номер моно. «Утверждено 05.10.2026 · 15:02», «Чеки 9/9», «Сдано 12.10.2026 · NV-0001».
- `.sstamp` малый на шагах «Как работаем»: слово + дата (`05.10`). Чётные повёрнуты +5°, нечётные −7°.
- `.rstamp` круглый на паспорте: текст по кругу «NIVEL · ТАШКЕНТ · ТЕСТ ПРОЙДЕН · 8 Ч ·», знак, дата.
- Цвет штампа — `#C8481A` на бумаге днём, `#A93F17` на бумаге ночью (`#E9E3D7` — иначе 3,7:1), `--accent` поверх сцены. Появление — «оттиск»: из `scale(1.6)` и `opacity:0` в `scale(1)` за 450 мс с `--ease-stamp`.
- Каждый штамп с датой — внутри примера NV-0001 и рядом стоит «образец/пример».

### 3.6. Бирки и пометки честности
- `.tag` — моно 11,5 px, рамка и текст `--accent-ink`: «пример · не оферта», «цены на 05.10.2026 · пример · не оферта».
- `.sample-mk` — чёрная бирка «ОБРАЗЕЦ» над верхним краем документа; на паспорте — наклеенный штамп «Образец» у верхнего края (не поверх графиков и таблиц).
- `.viz` — «визуализация · пример сборки» в углу сцены; в статичном режиме — «визуализация · пример сборки, не выполненный заказ».
- Подписи деталей (`.plabel`): компьютер — «Видеокарта RTX 5070 12 ГБ / 9 650 000 сум · пример», телефон — «Видеокарта 9,7 млн». | Ночной свет включается | щелчок: мерцание 0–260 мс, затем до полного за 500 мс — у рабочего света на шаге 01 и у лампы | ступенчатая кривая `flick()` |
| Сцена ↔ прокрутка | ScrollTrigger `scrub:true` при Lenis (`lerp:.12`), иначе `scrub:.5`; внутри сцены догон `cur += (target−cur)·0.16` | |

**Смена режима без перезагрузки.** `NV.setTheme(t)` ставит `data-theme`, на 1 с вешает `html.theme-shift` (переход только `background-color, color, border-color, fill, stroke, box-shadow, opacity`), обновляет `<meta name="theme-color">`, сохраняет выбор в `localStorage` (`nv-theme`, в try/catch) и шлёт событие `nv-theme`. Сцена твинит один параметр `S.m` 0 → 1: солнце гаснет, ночные источники набирают силу, фон и туман уходят в тёплый чёрный. **`S.m` меняет только интенсивности, цвета и фон — положение и видимость объектов зависят только от прокрутки `p`** (до 06.10.2026 лампа въезжала и улетала при переключении на шагах 01–03). Объект сцены, канвас и WebGL-контекст остаются те же (проверено `toggle_test.py`).

**Режим по умолчанию:** сохранённый выбор → иначе местное время посетителя, день 07:00–18:59. Вычисляется в `<head>` до первой отрисовки (без мигания). `?theme=day|night` — для проверки.

**Reduced motion.** `prefers-reduced-motion: reduce` или кнопка «Без анимации» (`nv-motion=off`): нет WebGL, нет Lenis, нет scrub; первый экран — обычная секция с сеткой из 5 кадров текущего режима; `.rv` и штампы видны сразу; смена режима — мгновенная.

## 6. Статичный режим и защита слабых телефонов

82 % посетителей — Android среднего уровня, поэтому WebGL — надстройка, а не основа.

1. **Постер сразу.** Первый экран рисуется из `frames/{day|night}-{d|m}1.webp` (`fetchpriority=high`), подписи и кнопки — HTML. Ничто не ждёт 3D.
2. **Ворота (`NV.gate`)** — WebGL не грузится, если: `prefers-reduced-motion`, `navigator.connection.saveData`, сеть 2g, `deviceMemory < 4` или `hardwareConcurrency < 4`, нет WebGL, программный рендер (SwiftShader/llvmpipe). **Телефон (`pointer:coarse` или ширина < 860 px) по умолчанию получает статичные кадры** — three.js (170 КБ) не скачивается. Рядом с «визуализация» — кнопка «3D-сцена» (SVG-куб): по нажатию сцена грузится сразу, выбор хранится в `nv-3d` (localStorage, try/catch) и сбрасывается, если проба не прошла. Lite — у телефона, включившего 3D, и при памяти/ядрах ≤ 4. Контекст WebGL для проверки создаётся только на компьютере.
3. **Ленивый старт без длинных задач.** three.js импортируется после `load` и `requestIdleCallback` (≤ 1,2 с). `init()` асинхронный: между текстурами, комнатой, корпусом, деталями, светом и PMREM — `scheduler.yield()` (или `setTimeout 0`).
4. **Прогрев.** До показа сцены — `renderer.compileAsync` в состоянии 05 (видны все объекты), затем текстуры на GPU по одной (`initTexture`) с паузами и один скрытый кадр. При прокрутке шейдеры больше не компилируются.
5. **Проба кадров — на самом тяжёлом состоянии 05** (≈ 300 вызовов отрисовки), 6 кадров: телефон и слабые — > 20 мс lite, > 33 мс статичные кадры; компьютер — 26 и 45 мс. Затем слежение: решение по первым 18 кадрам прокрутки — средняя < 30 к/с **или** p95 (второй худший кадр) > 50 мс → lite, повторно → статичные кадры (`renderer.dispose()`). В эмуляции телефона с включённой 3D проба дала 36–45 мс, и страница перешла на кадры до первой прокрутки.
6. **До загрузки GSAP** (на 3G 5–9 с) прокрутка уже двигает подписи и кадры: временный пассивный обработчик `NV.setP(NV.progress())` в `requestAnimationFrame`, снимается в `NV_BOOT`. Линия под шапкой — через `IntersectionObserver` на маркере вверху страницы, без чтения `scrollY` при разборе.
7. **Статичные кадры** — 5 состояний × 2 режима × 2 раскладки (`d` 1440 × 900, `m` 585 × 1266 = 390 × 844 при DPR 1,5), отрендерены этой же сценой (`render_frames.py` → `NV.scene.renderFrames`). Прокрутка переключает кадры кросс-фейдом 450 мс; грузится текущий и следующий, только для активного режима. Смена режима — кросс-фейд стопок кадров. Кадры показываются, пока сцена не готова (`!NV.sceneReady`), поэтому и на компьютере до старта 3D прокрутка не «замирает». На кадре 03 — HTML-подписи деталей с ценами: координаты `NV.FL` (доли ширины и высоты кадра) вписывает `render_frames.py`, страница пересчитывает их под `object-fit: cover` и `object-position`.
8. **Без анимации** — сетка из 5 кадров с подписями (2 колонки на телефоне).

Параметры для проверки: `?scene=force|static`, `?q=lite`, `?nofps`, `?nolenis`, `?motion=off`, `?theme=day|night`, `?lang=uz`, `?render`.

## 7. Перенос в Next.js (App Router)

1. **Режим до гидратации.** В `app/layout.tsx` — `<html data-theme="day" suppressHydrationWarning>` и inline-скрипт в `<head>` из прототипа (localStorage `nv-theme` в try/catch → иначе час 07–19), он же ставит `lang` и `theme-color`. Не использовать `next-themes` с классами — нужен именно `data-theme`.
2. **Токены.** `packages/ui/src/tokens.ts` (раздел 2.2) — источник; `tokens.css` генерируется из него и импортируется в `globals.css`. Компоненты пишут `var(--ink)`, не хардкод.
3. **Шрифты.** `next/font/google` с `subsets: ['latin','cyrillic']` для Brygada 1918, Fira Sans, Fira Sans Extra Condensed, IBM Plex Mono, Noto Sans Mono; переменные `--display/--sans/--cond/--mono`. Проверить, что подмножество включает U+02BB (в `latin-ext` у части семейств — добавить `latin-ext`).
4. **Сцена — отдельный клиентский чанк.** `const Scene = dynamic(() => import('@/scene/Workplace'), { ssr:false })`; монтировать только если `gate().ok` (на телефоне — только по кнопке «3D-сцена»), после `requestIdleCallback`. Процедурные canvas-текстуры в продакшне заменить заранее отрендеренными WebP в `public/scene/` (декодирование вне главного потока), статичную мелочь стола и ПК слить `mergeGeometries` / `InstancedMesh` — цель ≤ 120 вызовов отрисовки. Сцена слушает `nv-theme` / `nv-lang` (или общий zustand-стор) и не пересоздаётся при смене режима.
5. **Постер — серверный.** `<Image priority src={`/frames/${theme}-${layout}1.webp`} />` в той же sticky-сцене; для второго режима — `loading="lazy"`. Кадры лежат в `public/frames/`, пересобираются скриптом `render_frames.py` (headless Edge) при изменении сцены.
6. **Прокрутка.** GSAP + ScrollTrigger + Lenis подключаются там же, где сцена (не в общем бандле); на устройствах без `pointer:fine` Lenis не включать.
7. **Контент.** Тексты RU/UZ — из словаря (в прототипе `UZ{}` и `data-i` для текста, `data-ih` для разметки, `data-ia` для `aria-label`, `data-it` для `title`; `<title>` и `meta description` тоже переводятся), цены конфигуратора — из каталога с датой; сборка NV-0001 — одна константа для сметы, отчёта, паспорта и подписей 3D.
8. **Честность — в коде.** Бирки «пример · не оферта», «визуализация», «образец» — обязательные пропсы компонентов `Estimate`, `Receipt`, `Passport`, `SceneCaption`, не опциональный текст.
9. **Внешние ресурсы** — только cdnjs.cloudflare.com, cdn.jsdelivr.net/npm, unpkg.com и fonts.googleapis.com; в продакшне лучше самостоятельно собрать three/GSAP в бандл.
